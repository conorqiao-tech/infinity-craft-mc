# Reliability and helper work — explore.33

This update keeps Minecraft 26.3 / Java 25 and the pinned Fabric/Geyser stack. It includes the explore.27 original artwork, separate solid Convergence chestplate, existing wings and armor collection inventory. It does not change player permissions, AI approval gates, worlds or hosting settings.

## Destination preparation and discovery in explore.33

| Trigger | Previous behavior | Corrected behavior and regression |
| --- | --- | --- |
| A cross-mode move returns to a saved location whose terrain has unloaded. | Safety checks synchronously wait for native FULL chunks while the server thread is handling the move. | Shared native loading leases prepare the exact saved location across ticks. At most four new native requests start per server tick; no lease operation invokes the blocking native `getChunkFuture`. Inventory capture and participant saving happen only after a ready destination and successful teleport. |
| A Creative or Hardcore default search crosses missing collision chunks. | The search can synchronously generate many columns and their collision neighbors in one call. | Preserve all 1,089 original nearest-ring candidates, read at most 64 loaded columns per poll, and retain the actual one-block collision halo. The origin grid occupies 100 distinct chunks; a distant saved position can add four. This bounds requests and scanning, not total native generation work or whole-server lag. |
| A course becomes unavailable before the first preparation poll, then available again before the countdown ends. | A fallback course can supply the retained location, while the later final check accepts the originally chosen course. | Resolve the course once and reject its unavailability without fallback. A refused request stays terminal; a fresh request can recover after that exact course is repaired. |
| Movement, damage, death, disconnect or replacement of a player occurs during preparation. | A late loading result risks applying to a changed player/session. | Ordinary transfers cancel before profile capture. Jobs bind the actual player object, native connection, origin world/mode and request. Stale callers and late disconnect callbacks cannot cancel a newer session. OPs retain their gameplay bypass but still wait for technical loading and lose a pending privileged request if that permission is revoked. |
| An Odyssey discovery check reaches an incomplete local/reference chunk. | A periodic journal scan can ask for a synchronous FULL chunk. | Query only actually published chunks; defer incomplete data to the normal 20-tick retry. Existing discovery bounds, lore, progress, loot and saving remain unchanged. |
| Native course teleport refuses the move. | Food, course selection or the run can change despite the failed teleport. | Check native teleport success first; retain the prior course, run, food and saved state on refusal. |

Preparation times out after 600 game ticks, which is not a wall-clock deadline. The native nonpersistent loading ticket lasts 1,200 ticks and overlapping leases renew the same ticket. Canceling releases this module's tickets without canceling shared native generation futures. Runtime renewal/removal failure branches are source-reviewed; shutdown cleanup is best-effort after a native removal exception.

This path covers cross-mode moves and first-visit routing. Same-mode Hub arrivals, home/default-spawn commands and native respawn fallbacks retain their existing synchronous paths. The explore.32 packet measurements below are preserved historical evidence; they are not a new explore.33 timing measurement. The live server remains explore.26 pending installation approval.

## Connection-local capacity refreshes in explore.32

| Trigger | Previous behavior | Corrected behavior and regression |
| --- | --- | --- |
| Full Convergence armor renews native Health Boost and Absorption without changing the player's effective capacity or displayed vitals. | Each dirty capacity packet adds another health/absorption refresh group to the wearer and observers. | Attribute packets still arrive; duplicate refresh groups are omitted only after that connection has seen the actual capacity fields and unchanged projected vitals. The history holds at most 256 targets and is discarded when the connection ends. Native encoding tests cover real capacity changes, food/saturation, independently tracked viewers and ordinary unrelated metadata. |
| The true maximum changes above the shared 40-point client display, a tracked entity is removed/re-added, or a player respawns/rejoins or changes worlds. | A naive display-only/global cache could leave the HUD stale or mix different sessions. | Compare true double capacities, object/UUID identity and actual fields carried by each packet. Tracking, login/respawn, viewer and world changes invalidate the history. Native lifecycle tests cover same-ID and same-UUID reuse, real replacement-player respawn, fresh login and FIFO eviction; no authoritative attribute, health or equipment NBT is changed. |
| A relevant packet is sent outside the native server thread. | Concurrent projection and later native enqueue cannot share a reliable delivery history. | Permanently clear and disable that listener's history, then retain the stateless refresh path. Unrelated packets retain their identity without that work. Native asynchronous delivery/fallback tests preserve packet order and original values. |

`tools/benchmark_capacity.py` compares prebuilt explore.31 and explore.32 jars through real registered armor upkeep in fresh disposable worlds. Both connection/player tick counts and the server tick count advance exactly 120 after 40 warmup ticks; actual native effect renewals and observer tracking must remain present. Receipts are recorded only after native encoding succeeds. Two baseline/optimized pairs alternate order. In each run both viewers received three capacity packets. Each baseline viewer received three synthetic health/absorption refresh groups; each explore.32 viewer received zero. True health/absorption, attribute bases, native saved attributes/equipment and every equipped item component stayed unchanged. This is a count of eliminated duplicate groups, not live TPS, latency or total allocation evidence.

Measurement records, reports, logs and their hashes remain under `research/capacity-performance/2.13.0-explore.32/`; the explore.32 packages retain summary/provenance binding that version's exact tested mod, test jar and Java sources. Packaging rejects missing/replaced native test jars, zero/incomplete comparison pairs, changed raw evidence or summary/report disagreement. Full-stack and authentic device checks remain separate from this controlled measurement. The earlier fixture lacking native connection ticking failed its renewal assertion and was corrected; its quiet output was never accepted as a performance result.

## Reproductions and fixes

| Trigger | Previous behavior | Corrected behavior and regression |
| --- | --- | --- |
| The dashboard polls while the local tunnel agent or a status file read stalls. | The status request holds the world-control lock; Stop, commands and Java output logging wait behind it. Slow IPC also expires its own cache before returning. | One background refresh publishes cached data without holding the control lock during reads. Tests block each reader and remote IPC and verify controls/logging continue, only one refresh runs, completion timestamps are correct, stale rosters expire and late results cannot replace new settings. |
| `launcher.log` cannot be opened, or a reader thread cannot start. | A child starts before log acquisition and can escape the service cleanup list. | The log opens first. Spawn/start failures close allocated resources and terminate/reap that exact child. Tests include a real child and termination escalation. |
| File, terminal or dashboard logging fails while Java continues writing output. | The reader exits, potentially leaving Java blocked on a full stdout pipe. | Failed optional sinks are disabled individually; remaining output continues to drain. One diagnostic is attempted through working sinks. A real child writes more than a pipe can hold before READY while all sinks fail; READY and clean stop still complete. Native final output is drained before pipe closure. |
| A local roster has malformed timestamps, player fields or excessive size. | A TypeError can end the status response, and unknown player fields can appear in the response. | Bounded reads validate finite numbers and the supported schema; unavailable status replaces corrupt data. Only public name/UUID/mode/rank fields are returned. |
| Several players finish courses or trigger individual progression/gear actions. | Each action calls native `saveAll`, repeatedly compressing and writing every online player's files. | Immediate native player, stats and advancement saves cover only participants. Player trades still save both participants and retain their existing journal, verification and rollback. Actual-file tests preserve equipped gear and inventory while unrelated observers' save bytes remain unchanged. |
| A runner retries a completed course without beating its best. | Every finish saves all online players again. | Same-course slower finishes preserve the existing best without another action save. Changing the chosen course saves that participant immediately, even if a later run is slower. Mode transfers retain their own final save. Native-file tests cover both cases. |
| A leaderboard write fails, then the same score is synchronized after storage recovers. | The in-memory board already changed, so unchanged scores never retry the failed disk write. | A dirty flag clears only after successful persistence. An actual filesystem obstruction regression verifies recovery with the same score and preserves the obstructing file. |
| A host-status write stalls or fails during a game tick. | JSON serialization, temporary-file writes and replacement happen synchronously on the game thread every five seconds. | The game thread captures immutable values for one daemon writer. It holds at most one in-progress and one replaceable pending snapshot. Tests block preparation while game ticks continue, coalesce 1,000 submissions, verify retry/temporary cleanup, and prevent a closed writer from overwriting the next server's snapshot. |
| A player wears delivered armor or moves a shield offhand, then requests gear again. | Main-slot-only ownership checks treat equipped items as missing and grant duplicates or incorrectly request space. | Native inventory ownership includes armor and offhand. A real grant test preserves total counts and custom names even with a full main inventory. |
| Fresh backpack equipment textures are generated. | Replacing the complete layer drops `dyeable`, so saved Trail/Emerald/Dragon colors no longer affect Java rendering. | Texture refresh preserves layer metadata and extra layers. Resource checks verify dye settings; actual player-file tests preserve all three colors and style names. |
| A warmed mode transfer, first Hub visit or spawn command has no dry, in-border destination, or its course is blocked. | A missing destination can throw through the server tick or begin an unsafe transfer. The default search revisits earlier rings. | Resolve and validate before changing profiles or cursor items, report the unavailable destination, and clear the pending route. The search checks 1,089 unique columns, skips columns outside the border, and revalidates its per-server cached result. Native tests preserve inventory, equipment, cursor, profiles and obstructing terrain. |
| A dead Hardcore player requests respawn while its fallback destination is unavailable. | Native respawn can remove the old player before the mod's destination finder fails. | A passive preflight runs before that replacement. Failure sends a host-repair message and closes normally with the original player saved. A real 26.3 login task reloads that realm and inventory; repairing the border permits normal respawn. Anchor death consumes one charge; preflight, alive requests and End credits consume no extra charge. Ordinary Survival keeps its native single search. |
| A connection faults with the outbound STATUS encoder installed. | Native error handling tries a disconnect packet that STATUS cannot encode, causing a second encoder error. | Close through native completion with the original fault details. Eleven in-process codec tests cover response/pong, faults, phase changes, other disconnect protocols, timeout, skipped packets and closed channels. The specific trigger of the earlier live connection fault is still unknown. |
| Six Regular helpers compare several hostile targets. | Each tie comparison can scan the loaded helper roster again for shared focus. | Build one lazy identity set per helper control only when a comparison needs it. Later helpers still observe earlier helpers' current targets. Native tests keep independent candidate queries, sight/range checks, target priority and both player-target approvals. |

## Additional maintenance and tick fixes in explore.30

| Trigger | Previous behavior | Corrected behavior and regression |
| --- | --- | --- |
| A helper proposal expires, or a target dies/leaves, while its backup cannot be written. | An automatic save throws through a tick or lifecycle callback. | Revocation immediately removes the live session and makes the request terminal. Failed writes retry after five seconds with one diagnostic per failure streak; shutdown makes one dirty-only final attempt. Real filesystem obstruction tests preserve the original, prove recovery and reject reopening a stale target when startup cancellation cannot be saved. Explicit approval/consumption saves still fail before dispatch. |
| A clear RC plane candidate checks its nine overlapping parts. | Each part repeats a living-entity query; an obstruction overlay repeats each tick. | One broad query is followed by all nine exact native intersections, preserving empty union corners and alive/spectator exclusions. Block, border and loaded guards run first. Warnings are immediate and refresh every ten ticks; clearance resets them. Native query counters and world fixtures cover rotations, obstructions, recall and permission loss. |
| Native backpack shift-transfer repeatedly notifies the same final contents. | Each notification encodes all 27 slots again. Codec partial output can replace storage; an overstack accepted by the codec cannot be reopened. | A bounded copied-stack snapshot skips identical saves. Component changes persist immediately. Codec errors and invalid per-item counts leave original NBT and the snapshot intact. Real transfers, player serialization and count100/count65 fault/recovery checks verify conservation and retry. |
| API helper history validates up to 24 saved identities each tick. | Every identity searches the roster again by owner/name. | Direct saved-ID lookup still requires the same record object, exact owner/name and current OP4. Native tracking observes 24 lookups with no roster-entry traversal and rejects replaced/recreated records and permission loss. |
| A full Creative inventory has no gear picker. | The registered tick checks once, then its recovery method checks again. | Call recovery once: one scan of 36 slots. Real direct slot replacement, full inventory and next-tick recovery checks preserve immediate behavior without relying on an inventory revision counter. |
| A navigator checks ownership. | It copies custom NBT twice and parses the owner UUID before comparison. | One copy checks the recovery-compass item, native numeric marker and exact canonical owner UUID. Native tests retain accepted numeric marker types and reject malformed/foreign ownership without changing the tag. |

The counters establish fewer repeated operations, not a whole-server TPS or latency improvement. Capacity-packet amplification during unchanged armor effect renewals remains a separate optimization candidate. Both chestplate choices and the existing artwork remain available. No live installation is implied by the source version.

## Player checks after an approved installation

1. Reconnect and accept the updated resources. Open Creative inventory's **Infinity Gear Picker**, then **Aurora Set** or **Convergence Set**. The solid chestplate and the existing winged item are separate choices.
2. Equip armor and a shield, then repeat **Armor & tools → inventory**. Existing equipment and custom names should remain; no extra copies should appear.
3. Check Trail, Emerald and Dragon backpacks on a pack-enabled Java client. Also check iPad armor, glint, slot visibility, wings and touch transfers. These rendered device behaviors still require an authentic client check.
4. Pick a different minigame, finish it slower than your existing best, then reconnect. Your choice and faster best should remain. A later save/reload remains covered by native-file tests.
5. Check the private dashboard while the game runs: status may briefly say unavailable during refresh, but current controls and logs remain responsive.
6. With six Regular helpers, check Follow and Guard against visible hostile mobs and a blocked sight line. Helpers must not attack players without both exact target approvals. Use a disposable world for combat and unsafe-spawn tests.

The opt-in `tools/benchmark_helpers.py` compares prebuilt explore.28 and explore.29 mod jars with a prebuilt test jar, Java 25 and a complete pinned cached runtime. It uses fresh temporary GameTest worlds, registers only its measurement test there, and never copies live worlds, credentials or settings. It records file hashes, raw counters and instrumented timings. The normal native suite explicitly excludes this expensive benchmark.

This does not make the server immune to lag, disk failure or client crashes. Native durability APIs still log some storage errors rather than raising them; trades retain explicit file verification. The atomic telemetry rename has a narrow shutdown guard. A disk that never returns can still delay that final rename/shutdown. A cold spawn search can still synchronously request up to 81 chunks. Controlled Regular-helper measurements do not establish Ultimate Finals performance, real multiplayer TPS, iPad rendering or public remote joins. An empty server normally pauses after 60 seconds, so an old roster snapshot is unavailable rather than proof of a stopped server. See VALIDATION.md for measured checks and the separately verified live version.


## Additional client-update and tick fixes in explore.31

| Trigger | Previous behavior | Corrected behavior and regression |
| --- | --- | --- |
| Unchanged health/absorption metadata or non-capacity armor/movement attributes pass through a tracking bundle. | Projection eagerly allocates discarded lists, attribute packets and metadata values for unchanged inputs. | Random-access list bundles copy only after their first changed child; attribute copies begin only when capacity needs projection; metadata compares value and native serializer first. Native copy-site counters cover 200 unchanged children, late changes, source identity/order and unchanged capacity refresh. These are allocation-site counts, not JVM memory or live TPS measurements. |
| An original grouped update contains an unchanged nested bundle. | The temporary list flattens children, but an unchanged flag returns the original nested bundle that cannot be sent as nested wire bundles. | The outer group treats nesting as a change and owns a flat list. Native outbound tests preserve child order and shared originals. |
| A grouped update uses a one-shot iterable whose children need no projection. | Projection consumes the iterator and returns the exhausted input. | The generic single-pass path always materializes its already-collected children, so subsequent encoding can traverse them again. Native tests cover unchanged and changed one-shot inputs, one input traversal and repeatable output. |
| The normal Convergence tick updates the online players. | A fresh HashSet and one UUID insertion per player are constructed only to prune offline state. | Native PlayerList UUID lookup prunes state without rebuilding that set. Four native lifecycle cases preserve living selections/cooldowns/fall tracking, remove actual death/disconnect state and retain existing same-UUID reconnect/age-reset semantics. |

Capacity update packets still refresh the HUD, including true-capacity changes above the shared 40-point display and resets to ordinary values. Suppressing repeated refresh packets is deferred until connection-local tracking, respawn, dimension change and removal invalidation are separately verified. No real-client frame-rate, multiplayer capacity or lag-proof result is claimed.
