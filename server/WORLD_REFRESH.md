# Regenerate old terrain after an installed mod update

This is a destructive **private owner opt-in** for the Minecraft 26.3 launcher. Public downloads keep existing worlds by default. Regeneration replaces unprotected terrain, builds, portals, block-container contents and ordinary entities in every dimension, including Creative, Hardcore and game worlds. The bounded built-in hub footprint and its generation marker remain together; course markers permit the native builder to reconcile missing course blocks safely. Natural structures use the installed generator when chunks are generated again; rarity still applies.

When its existing marker is present, the hub retains its **9×9 chunks** centered on the origin, covering all six lobbies, bridges, signs and decorations. The launcher never deletes lobby/course provenance while retaining their terrain fragments. Course reconstruction still preserves conflicting player builds and may leave that course unavailable instead of overwriting them.

Player saves (all mode inventories, armor, XP, stats, advancements and personal backpacks), ranks, rewards, records and private settings remain intact. The launcher keeps exact native terrain, POI and entity records for **5×5 chunks** around saved player positions, alternate-mode positions, respawns, homes, helper positions/anchors and owned tameable pets. This retains their floors, nearby builds/chests and edited entity state. The End arena keeps **17×17 chunks** around the origin, plus existing gateways and their landing areas. Global metadata, seed, gamerules, world borders and End boss progress remain. Already unsafe saved locations are not repaired; players can use the existing safe mode/lobby routing.

Entities outside protected areas are archived with their terrain, avoiding duplicate old mobs when world generation populates new chunks. Named/leashed livestock, dropped items, projectiles, allays, villagers, armor stands, item frames and vehicles outside protected areas are not treated as tameable pets. Players' embedded riding-vehicle data remains untouched. Helpers are not portable inventory items in this mod; an unlocated roster UUID cancels refresh rather than risking helper loss. Old structure starts inside retained chunks also remain; nearby generation can retain their old layout. A new incompatible Minecraft/save format requires separate review.

Only an installed Infinity mod release change triggers regeneration: its own `fabric.mod.json` version and pinned JAR checksum are compared with the last applied release. A launcher/Geyser-only package version change does not trigger it. Restarting the same release keeps terrain. Before any refresh, the launcher makes a stopped-world ZIP, checks its integrity and compares every archived world file with the stopped save. It stages compact copies of protected chunk records without rewriting their NBT, then moves old terrain into a private recovery folder under `backups/Terrain-Refresh-*`. An interrupted move or protected-copy write rolls back before the next startup backup and Java launch. A completed refresh is recorded before Java starts to prevent a repeat. Recovery preserves the owner's current enable/disable choice.

To opt in, save and stop the server and create `.world-refresh.json` in its root:

```json
{"format": 1, "enabled": true, "safety_strategy": "protected_areas", "last_release": "", "refresh_next_start": false}
```

The first start records the current release without clearing terrain. A later mod update refreshes it. Set `refresh_next_start` to `true` only when intentionally requesting an immediate refresh, including on the same release. Set `enabled` to `false` before starting to retain terrain through later updates. A malformed policy or unmatched/corrupt backup stops startup before regeneration. The converted 26.3 save layout is required; never downgrade a converted world.

Recovery instructions, the original policy, moved paths, protected chunk counts, preserved file checksums and verified full-backup checksum are recorded in each private refresh folder. Save and stop before recovery; preserve newly generated terrain elsewhere before replacing it with old terrain, and disable refresh before starting restored terrain. Unsupported compression, malformed player locations, missing helpers, damaged/external chunk records and excessive retained-memory requirements cancel the operation before moving terrain. Native region files and the total compact retained data are limited to 256 MiB each; decoded NBT/external payloads are limited to 64 MiB. Existing saves remain intact when a limit is exceeded.

## Exact-name owner bans

The independent private `.owner-join-rules.json` accepts `{"format":1,"blocked_names":["AccountName"]}`. The launcher watches native authenticated Java login records, matching complete account names without case sensitivity. The existing Floodgate `.` prefix is recognized for Bedrock; a matching joined account receives a native account ban and disconnect. Chat, partial names and unrelated display labels do not trigger it. Remove a name from this policy and use the normal native pardon command if the owner later allows that account. Public packages include no blocked names or policies.
